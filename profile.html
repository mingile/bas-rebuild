  • 건물마다 설비 배치와 포인트 바인딩이 모두 달라 공통 화면 하나로 처리할 수 없었습니다. 그래서 건물 홈과 메뉴를 건물 단위로 각각 설계하고 구성했습니다.
  • 화면 설계 건물 홈 — 건물 전경과 기본 정보(용도·규모·연면적·준공·공조기 대수)를 한 화면에 배치해, 관제 화면에 들어오자마자 어떤 건물을 보고 있는지 알 수 있게 구성
  • 템플릿 활용 상단 메뉴 — 기본 메뉴 템플릿을 바탕으로, 건물마다 다른 설비 구성에 맞춰 메뉴 항목을 화면별로 다르게 적용
  • 직접 구현 알람 버튼 — 알람 콘솔은 플랫폼 기본 기능을 활용하고, 메뉴 바의 알람 버튼이 알람 발생 여부(이벤트)에 따라 동적으로 바뀌도록 구현. 운영자가 어느 화면에 있든 알람 발생을 바로 알아챌 수 있게 했습니다.

개인 프로젝트 · Next.js / TypeScript / Notion API / MongoDB · Vercel

개인 운동 기록을 세션 단위로 입력·저장하는 모바일 중심 웹앱입니다. 남을 위한 서비스가 아니라 제가 매일 쓰면서 겪은 불편을 풀려고 시작했습니다.

1기록은 로컬이 기준, Notion은 동기화 대상

localStorage를 단일 출처(SSOT)로 두고 Notion DB를 선택적 동기화 계층으로 분리했습니다.

외부 서비스가 장애여도 기록 저장 자체는 막히지 않도록 의존 방향을 정했습니다.

2기다리지 않는 저장

운동을 마치고 Notion에 저장할 때 응답이 올 때까지 앱을 켜 두고 기다려야 했습니다. 요청 이후 처리를 서버 쪽 큐로 분리하고, 재시도·ack와 멱등 키로 중복 쓰기를 막았습니다.

3캐시 전략을 대상별로 분리

Service Worker에서 app shell은 cache-first, 외부 연동 상태 API는 캐시를 우회하게 했습니다.

오래된 상태 값 때문에 동기화가 잘못 일어나는 것을 막기 위해서입니다.

4Next.js를 고른 이유

Notion API는 클라이언트에서 직접 부를 수 없어 서버 쪽 코드가 필요했고, 서버리스로 설정 없이 무료 호스팅을 하고 싶었습니다. Vitest 단위 테스트를 두고 Vercel에 배포했습니다.
